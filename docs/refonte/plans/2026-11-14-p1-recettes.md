# P1 Recettes : plan d'exécution

> **Pour l'exécutant** : skills à citer à chaque étape : `atoumweb-design`, `superpowers:executing-plans` (exécution), `superpowers:verification-before-completion` (avant de dire que c'est fini). Les étapes utilisent des cases `- [ ]`. Ici le « test d'abord » est **la recette elle-même** : on la voit rouge pour la bonne raison avant de la toucher, puis verte.

**Objectif** : chaque recette des sept entrées F5, F6, F12, F21, F22, F32, F39 est **verte, ou retirée pour une raison écrite**, sans changer un écran, une donnée ni une règle métier.

**Architecture** : un journal unique (`docs/refonte/plans/2026-11-14-p1-recettes-journal.md`) reçoit, pour chaque script, l'échec relevé, la catégorie de cause (A attente périmée, B obsolète, C mode d'emploi, D fragile, E défaut du produit) et le résultat. Le diagnostic de **tous** les scripts précède tout traitement ; un point d'arrêt te montre le tableau et la liste des retraits.

**Stack** : scripts Node/Electron de `scripts/` et `scripts/fixtures/` ; harnais commun `scripts/check-ux-v2-lot01a-real-ui.cjs` (le lanceur remplace son point d'entrée `require('./fixtures/02c-search-scenarios.cjs')` par le scénario visé).

**Fiche** : `docs/refonte/plans/2026-11-14-p1-recettes-design.md` (validée le 14/11/2026 : approche A ; défaut produit signalé sans correction ; liste des retraits validée par Carlos avant effacement). Parent : `2026-11-14-passe-finitions-design.md`.

## Contraintes globales

- **Ne touche pas** `src/`, les données, ni la préproduction `C:\DEV\03_LIVRAISONS\AtoumWeb\Manager-Claude-Codex-20261110\Workspace` (aucune écriture ; les recettes tournent sur des copies temporaires).
- **Une attente n'est jamais détendue pour passer au vert** : elle est corrigée parce qu'elle était fausse, ou la recette disparaît parce que le parcours n'existe plus.
- **Un seul Electron à la fois**, en tâche de fond ; attendre un marqueur de fin avant de lancer le suivant. Les scripts natifs de référence se lancent **sans option**.
- Écrire les scripts d'édition avec l'outil d'écriture (jamais en bloc shell) ; fins de ligne contrôlées par `C:\DEV\Livrables\Cadrage-parcours\outils-edition\eol-report.cjs` (`--fix` après un script d'édition).
- Les lanceurs génèrent des fichiers temporaires dans `outputs/` (ignoré par git) : vérifier qu'aucun ne reste après une exécution interrompue.
- Budgets inchangés : petits textes 625, `!important` d'`ui-consistency-v2.css` 86.
- Pas de tirets longs, tutoiement, jamais le mot interdit (mémoire). Aucun commit avant ta validation du journal.
- **Écart de méthode (mon choix, à contrôler)** : la fiche prévoyait une copie détachée du dernier commit. Comme P1 ne touche pas `src/` et que seul un document est non suivi, le worktree principal **est** le dernier commit pour le code ; je n'utilise la copie détachée que si un point E m'oblige à toucher `src/`.
